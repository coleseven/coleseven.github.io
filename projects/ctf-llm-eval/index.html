Overview

This is a continuation of the domain-specific cybersecurity LLM research project at USCB. After the team trained nanochat (a 1.38B-parameter model based on Andrej Karpathy's nanoChat) and I built the training datasets, I independently designed an evaluation harness and ran six systematic experiments to push the model from producing valid CTF challenge specs 17.5% of the time to 97.5% — an 80-percentage-point improvement using only a single RTX 3080 Ti.

Each experiment demonstrates a different ML technique — inference-time scaling, hyperparameter search, self-play data curation, retrieval-augmented generation, preference optimization, and technique composition — with all results measured against the same deterministic structural validator and 40 held-out evaluation prompts, making every comparison apples-to-apples.

The Problem

The SFT-v2 baseline model (LoRA rank 32, targets c_q/c_v, trained on 525 augmented examples) could generate text that looked like CTF challenge specs, but only 17.5% of its outputs were fully valid — meaning all seven required fields (title, category, difficulty, description, artifact, flag, solution) were present and the flag used the correct flag{...} format. The main bottleneck was the flag field: only 22.5% of outputs included a properly formatted flag.

The goal was to find out which post-training and inference techniques could close this gap, how they compare, and whether they compose.

Eval Framework

Every experiment shares the same evaluation pipeline: 40 held-out prompts spanning 7 CTF categories and 3 difficulty levels, scored by a deterministic structural validator that checks each of the 7 required spec fields. The key metrics are:

  • SV% — Structural Validity: all 7 fields present and non-empty
  • FV% — Fully Valid Strict: SV plus the flag matches flag{...}
  • MFS — Mean Field Score: average fraction of fields passing (0.0–1.0)

The Experiments

1. Best-of-N Rejection Sampling

Generate N candidates per prompt and select the one with the highest validator score — trading inference compute for quality with zero additional training. This is the simplest inference-time scaling technique: no reward model, no retraining, just a deterministic verifier the pipeline already has.

The biggest jump comes from N=1 to N=2 (+17.5pp SV%), confirming the model has high output variance. The flag field is the primary beneficiary — its pass rate climbs from 22.5% to 97.5% across the sweep, consistent with a binomial model of per-attempt success probability. No mode collapse was detected at any N.

2. LoRA Configuration Sweep

Grid search over rank {8, 16, 32, 64} and target projections {c_q/c_v, c_q/c_k/c_v, c_q/c_k/c_v/c_proj} — 12 configurations total, all trained on the same 525-example dataset with alpha = 2x rank.

ConfigParamsSV%FV%MFS
r8_qkvp3.8M87.5%35.0%0.889
r16_qkv3.5M95.0%27.5%0.875

r32_qv (baseline)4.7M80.0%7.5%0.832
r8_qv (worst)1.2M52.5%10.0%0.711

The key finding: target selection matters more than rank. At rank 8, expanding from 2 to 4 attention projection targets improves MFS by +0.178 — while increasing rank from 8 to 64 on the same targets gains only +0.135. The winner, r8_qkvp (rank 8, all 4 projections), achieves the best overall quality with fewer parameters than the baseline. This contradicts the common heuristic of "just use c_q and c_v" from the original LoRA paper, which was validated on much larger datasets.

3. Self-Play SFT (Data Flywheel)

An iterative loop: generate outputs with the current model, filter by the structural validator (keep only outputs scoring at least 6/7 fields), append the valid outputs to the training data, retrain from the base checkpoint, and repeat.

RoundExamplesSV%FV%MFS
0 (baseline)52577.5%17.5%0.829

357180.0%30.0%0.868

The flywheel works — slowly. After 3 rounds, FV% improves by +12.5pp and the data keep rate rises from 20% to 33%, confirming a positive feedback loop. But the model's own valid outputs are similar enough to existing data that the marginal signal is weak. Self-play is useful for bootstrapping from very little data, but it is not the highest-impact method.

4. RAG-Augmented Generation (Negative Result)

Retrieve a relevant training example at inference time as few-shot context, testing three strategies: category match, category + difficulty match, and TF-IDF similarity.

StrategySV%FV%MFS
No RAG (baseline)77.5%17.5%0.829
Category match35.0%20.0%0.604
Category + difficulty25.0%10.0%0.546
TF-IDF similarity22.5%7.5%0.550

All RAG strategies performed worse than no retrieval. The model was fine-tuned on single-turn conversations and has never seen a prompt that includes a prior example followed by "now create a different one." The prepended context is out-of-distribution — the model interprets it as part of the user's request rather than as a formatting hint, causing confused and fragmented outputs. RAG requires either a model pre-trained for in-context learning or explicit few-shot fine-tuning. Honestly reporting negative results matters for credible research.

5. Direct Preference Optimization (DPO)

Train the model to prefer structurally valid outputs over invalid ones, using the structural validator as an automated reward signal. For each training prompt, generate two candidates, score them, and keep pairs where the score gap is at least 0.1. This produced 59 preference pairs from 100 prompts — no human annotation needed.

MetricBaselineDPODelta
SV%77.5%85.0%+7.5pp
FV%17.5%72.5%+55.0pp
MFS0.8290.939+0.110
Flag%22.5%85.0%+62.5pp

DPO is the strongest single training-time technique by a wide margin. The flag field jumps from 22.5% to 85.0% — DPO excels at learning specific format rules. The key insight: any deterministic verifier can serve as a DPO reward signal, making this pattern applicable to any task with a programmatic quality checker (code compilation, test passing, format validation) without human annotation.

6. Stacking (Technique Composition)

Stack the best techniques incrementally to test whether they compose or conflict: r8_qkvp LoRA config + DPO + self-play + Best-of-N.

ConfigurationSV%FV%MFSFlag%
r8_qkvp + DPO92.5%72.5%0.95075.0%
+ Self-playregressed in every round (FV% dropped to 37–47%)
+ BoN (N=2)97.5%90.0%0.98292.5%
+ BoN (N=4)97.5%92.5%0.98995.0%
+ BoN (N=8)97.5%97.5%0.996100.0%

Two findings emerged. DPO and Best-of-N compose — they operate at different levels (training-time model improvement vs. inference-time selection), and DPO halves the N required: N=8 on the DPO model matches N=16 on the SFT-v2 baseline, cutting inference cost in half for the same quality. Self-play conflicts with DPO — retraining LoRA weights from scratch overwrites the DPO-learned preferences, causing every self-play round to regress. The design principle: techniques compose when they operate at different abstraction levels and conflict when they compete at the same level.

The core practical result: training-time optimization multiplies the effectiveness of inference-time compute. DPO + BoN(N=2) at 2x inference cost matches what BoN alone needs N=8 for. All six experiments ran on a single RTX 3080 Ti in about 16.5 hours of total GPU time.

What I Learned

  • DPO with a deterministic verifier is a powerful and underused pattern. Any task where you can programmatically check output quality can skip human preference labels entirely.
  • Negative results teach as much as positive ones. RAG failing on a small fine-tuned model highlights the gap between how RAG works on large pre-trained models (which learn in-context learning during pre-training) and small domain-specific ones.
  • Hyperparameter sweeps pay for themselves. The LoRA sweep found that the original "reasonable default" ranked 9th out of 12 — a result I would never have guessed without systematic search.
  • Composition has rules. Techniques compose across abstraction levels (training + inference) but conflict within the same level (two methods that both retrain LoRA weights). This principle generalizes beyond this project.
  • An eval harness is the most important thing to build first. Having a deterministic, automated eval pipeline made it possible to run six experiments and compare them fairly. Without it, I would have been guessing.
